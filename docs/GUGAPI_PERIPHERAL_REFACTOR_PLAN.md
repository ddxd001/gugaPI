# gugaPI 外设可靠性重构执行方案

## 1. 范围

本方案只覆盖主控 `gugaPI/` 工程，不修改 `MotorDriver/` 子工程，不改变
`services/scheduler.h/.cpp`、任务周期或 `Scheduler_AddTask()` 接口。

目标是在保留现有板级 API 和 Shell 入口的前提下，让外设初始化、运行期数据、
超时和故障状态可检测、可降级、可诊断。

## 2. 执行顺序

1. 修复 ICM45686 SPI 超时与真实初始化结果传递。
2. 给 IMU、灰度采样增加 `valid/last_update_ms/error_count/last_status`。
3. 建立逐设备启动自检表，区分 `degraded` 与 `motion-inhibit`。
4. 增加 INA219 有界采样、滞回、连续计数、锁存和可选运动禁止。
5. 抽取共享 I2C 控制器层，迁移 OLED、FRAM、INA219，并保留
   `I2cDiag_*` 兼容接口。
6. 完成 LIS3MDL 驱动与共享 SPI 板级封装。
7. 增加 LoRa 帧、CRC、序号、ACK、重试和接收队列；原始模式保留。
8. 在灰度完整帧发布后增加校准、归一化、线位置和异常通道检测。
9. 删除没有硬件对象的通用 ADC/PWM 占位命令。
10. 为每个完成模块编写启动、API、参数、Shell 和验证手册。
11. 执行 SysConfig、TI Clang 5.1.1、差异检查和资源占用验证。
12. 在不改变调度器接口的前提下扩展按键事件状态机，并将 ICM45686 提升到
    200 Hz / 1 MHz SPI；保留原有按键和 IMU API。

## 3. 兼容性约束

- 原有 `Board_*`、IMU/灰度数据获取和 `I2cDiag_*` 调用继续可用。
- FRAM 配置格式升级为 v6；可读取 v1 至 v5，旧格式加载后使用新字段默认值。
- LoRa 协议上电默认关闭，不抢占原始 UART 接收数据。
- INA219 自动运动禁止默认关闭，必须根据实际电池和负载完成参数整定后启用。
- 所有同步硬件等待必须有明确超时；本重构不承诺任务隔离。
- 按键继续使用 5 ms 周期扫描和 20 ms 软件消抖；外部中断不作为长短按判定依据。
- ICM45686 本阶段继续使用同步 14 字节突发读取；只有引入 FIFO 批量读取后才考虑
  SPI DMA。

## 4. 完成判据

- CCS 只构建 `gugaPI` 时 0 编译错误、0 源码警告。
- SysConfig 可以重新生成，无引脚或外设冲突错误。
- `git diff --check` 通过，`MotorDriver/` 无源码差异。
- 每项软件功能有对应设备手册。
- 实物验证项与仅编译验证项明确分开；未上板项目不得标为硬件通过。

## 5. 当前状态

软件实现和设备手册已完成；MSPM0 SDK 2.10.00.04、SysConfig 1.26.2 与 TI Clang
5.1.1.LTS 阶段构建已通过。按键事件时序、ICM45686 的 1 MHz mode 3 波形与 200 Hz
连续采样仍需在实物上验证。
