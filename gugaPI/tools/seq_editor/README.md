# gugaPI 中文图形化序列编辑器

在本目录运行 `start.bat`，或执行 `server.ps1` 后打开 `http://localhost:8080/`。推荐使用 Chromium 系浏览器，以便通过 Web Serial 连接 gugaPI Shell。

## 基本流程

1. 从左侧动作库拖入动作块，在右侧设置带单位和范围的中文参数。
2. 从动作块右侧端口拖到目标动作。绿色为完成路径，红色为失败/超时路径；失败/超时端口不连接时会终止当前序列并安全停车，连接其他动作时按红色路径执行。循环的“循环完成”属于正常路径，仍必须连接。
3. 先用“试运行当前画布”下发 RAM 表。编辑器依次执行 `run clear/add/validate/dump/start`，回读不一致时不会启动，也不会写 FRAM。
4. 确认流程后用“保存到 FRAM”。覆盖前会确认，保存后通过 `seq dump` 逐项比对。
5. 发生异常时使用页面顶栏始终可见的“紧急停止”。它会依次取消序列、比赛、航向、循迹和底盘控制。

运动测试前必须架空车轮并清理机械运动范围。真实设备验收建议临时使用槽位 7，并在结束后恢复其原内容。

## 使用帮助

顶部“使用帮助”栏目是随上位机发布的离线中文知识库，不需要连接设备。
它覆盖串口连接、比赛/调试模式、安全操作、序列、仪表盘、参数、终端、
命令库和常见故障，并为动作库中的每个模块提供参数、出口行为、接线案例
和注意事项。搜索支持中文名称、模块类型、ActionOp 和错误关键词；帮助页
只读，不会发送串口命令或修改当前序列工程。

## 实时仪表盘

仪表盘启动时不选择图表，也不会自动开启 MCU 遥测。连接串口后，从左栏
从运行、底盘、循迹与道路、转向过程、IMU、灰度传感器或系统健康分类中
选择一张图表，上位机会发送对应的
`telem on <profile> <period_ms>` 命令；固件只返回该图需要的字段。
切换到其他页面时遥测暂停，返回仪表盘后恢复本次会话选择。右栏显示当前
字段的协议名称、工程单位、含义和实时裸值；枚举和布尔字段同时显示中文
解释。页面重新加载后选择不会恢复，MCU 也不会自动开始发送遥测。

## 工程 JSON v2

工程文件使用 `format: "gugapi-sequence-project"`、`version: 2`，保存工程名、绑定槽位、语义参数、节点坐标及端口连线。浏览器会自动保存到 `localStorage`，也可导入或导出 JSON。导入或打开 v1 工程时，编辑器会自动把旧 `branch`、按键/灰度等待和运动完成条件迁移为通用条件。

图形坐标不会写入 MCU。编译器从“开始”节点按稳定广度优先顺序生成最多 64 条指令，并把所有连线转换成明确索引；FRAM 使用 SeqStore v2 的 14 字节指令和 8 个槽位。固件首次发现 v1 存储时会执行可恢复迁移。

## 本阶段动作

编辑器提供 16 类动作块：直行、定距、转向、循迹、循迹通过路口、定时等待、通用条件、计数循环、停车、结束、三种 LED 动作和三种蜂鸣器动作。直行和循迹可选择按超时结束，或在运动中持续判断通用条件。

“循迹通过路口”从当前黑线开始，在下一个路口按固定方向左转、直行、右转或掉头，重新捕获黑线后从绿色端口继续。掉头可选择“滚动圆弧”或“停车原地”；节点只开放方向、正向循迹速度和 50 ms 步进的整体超时。目标出口不存在、捕线失败或控制器异常时停车并走红色端口。连续两个该节点以及中间经过计数循环节点时会保留循迹运动交接；连接到普通动作或结束节点时先停车。

“循环”节点的次数范围为 `1..1000`，默认 2 次，表示循环体实际执行次数；次数 1 会执行一次，0 不表示无限循环。“执行循环体”出口至少连接一个动作，循环体正常路径再连回循环节点；“循环完成”出口连接循环后的动作。多个循环及嵌套循环均受支持。含循环的工程不做静态展开，运行时仍受整条序列 300 秒上限保护；无循环工程会按 300 秒上限检查各步骤最长时间之和。

工程 JSON 仍为 v2，FRAM 仍使用 SeqStore v2 的 14 字节指令，不迁移已有槽位。循环使用操作码 18，“循迹通过路口”使用操作码 19。编辑器在上传包含操作码 19 的工程前检查固件命令目录；旧固件不支持时会在清空 RAM 表前提示升级。即使绕过上位机检查，旧固件也会把未知操作码判为无效，不会启动运动。

通用条件覆盖按键电平/按下事件、灰度与路口、IMU、底盘反馈与相对编码器距离，以及应用控制状态；支持 `==`、`!=`、`<`、`<=`、`>`、`>=` 和位包含比较。条件数据无效或过期时立即走失败路径。Button2 始终保留为比赛急停，因此含 Button2 条件的序列只能在 RAM 中调试，不能保存为比赛序列。

任意 Shell 命令不会作为动作块执行；后续功能应通过新增固件 `ActionOp` 扩展，以保持脱机 FRAM 运行能力。
