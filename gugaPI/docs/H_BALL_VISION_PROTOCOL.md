# H题滚球视觉接口：MaixCAM Pro与gugaPI对接协议

## 1. 接口目标

本协议只传输MaixCAM识别得到的钢球位置，不传输图像，不控制达妙电机，也不承担MaixCAM参数配置。

- MaixCAM负责图像采集、钢球识别、透视校正和像素到物理位置转换。
- gugaPI负责状态估计、滚球闭环、DM-G6220控制和安全处理。
- 第一版使用固定长度、单向、自动发送协议，不包含版本协商、消息类型、ACK或远程配置。

## 2. 电气和串口参数

| 项目 | 约定 |
| --- | --- |
| 电平 | 3.3 V TTL |
| 波特率 | 115200 |
| 数据格式 | 8N1 |
| 流控 | 无 |
| 发送周期 | 20 ms，固定50 Hz |
| gugaPI接收 | PB22 / UART4_RX，连接MaixCAM TX |
| gugaPI发送 | PB21 / UART4_TX，第一版不使用 |
| 地线 | 两板必须共地 |

MaixCAM上电并完成初始化后自动开始发送。无线图传、录像或网络异常不得阻塞串口位置流。

MSPM0G3519的PB21是UART4_TX，PB22是UART4_RX；已在gugaPI SysConfig中固定该复用。

## 3. 坐标定义

- 原点：摆杆中心点O；
- 正方向：从O点指向摆杆受驱动端；
- 单位：0.1 mm；
- 合法物理范围：`-1250..+1250`，对应 `-125.0..+125.0 mm`；
- MaixCAM必须完成透视校正后再发送物理位置，gugaPI不接收原始像素作为控制量。

例如：

- `+500`表示`+50.0 mm`；
- `-500`表示`-50.0 mm`；
- `0`表示中心点O。

## 4. 固定12字节帧

所有多字节整数均为小端序。

| 字节偏移 | 长度 | 类型 | 内容 |
| ---: | ---: | --- | --- |
| 0 | 1 | uint8 | 帧头 `0xA5` |
| 1 | 1 | uint8 | 帧头 `0x5A` |
| 2 | 1 | uint8 | 帧序号 |
| 3 | 1 | uint8 | 状态标志 |
| 4 | 2 | int16 | 钢球位置，单位0.1 mm |
| 6 | 2 | uint16 | 识别置信度，0～1000 |
| 8 | 2 | uint16 | 图像采集到UART发送的延迟，单位ms |
| 10 | 2 | uint16 | CRC16-Modbus，小端 |

帧序号每发送一帧加1，`255 -> 0`自然回绕。无论是否识别到球，帧序号都继续增加。

### 4.1 状态标志

| 位 | 名称 | 含义 |
| ---: | --- | --- |
| bit0 | `BALL_FOUND` | 当前帧识别到钢球 |
| bit1 | `CALIBRATION_VALID` | 像素到物理位置标定有效 |
| bit2 | `CAMERA_OK` | 摄像头和图像处理正常 |
| bit3～7 | 保留 | 第一版必须写0 |

gugaPI仅在bit0、bit1、bit2全部为1，置信度达到阈值且位置范围合法时使用该位置。

### 4.2 未识别到钢球

MaixCAM没有识别到球时仍须按50 Hz发送：

```text
BALL_FOUND = 0
CALIBRATION_VALID = 当前标定状态
CAMERA_OK = 1
position = 0
confidence = 0
```

这样gugaPI可以区分：

- 完全收不到正确帧：串口断线、MaixCAM掉电或程序停止；
- 持续收帧但 `BALL_FOUND=0`：通信正常，但钢球识别失败。

## 5. 视觉处理延迟

延迟字段定义为：

```text
进入UART发送队列的时间 - 对应图像完成采集的时间
```

单位为ms，取整数并限制在 `0..65535`。

gugaPI以UART接收完成时间减去该延迟，近似得到钢球位置的实际采样时间。若MaixCAM暂时无法测量，可先填0，但双方联调时应实测并补齐。

## 6. CRC算法

使用CRC16-Modbus：

- 多项式：`0xA001`；
- 初始值：`0xFFFF`；
- 输入范围：字节0～9，包括帧头；
- 结果低字节先发送。

参考伪代码：

```c
uint16_t crc16_modbus(const uint8_t *data, uint16_t length)
{
    uint16_t crc = 0xFFFF;
    for (uint16_t i = 0; i < length; i++) {
        crc ^= data[i];
        for (uint8_t bit = 0; bit < 8; bit++) {
            crc = (crc & 1U)
                ? (uint16_t)((crc >> 1) ^ 0xA001U)
                : (uint16_t)(crc >> 1);
        }
    }
    return crc;
}
```

## 7. 固定测试向量

### 7.1 O点、置信度1000、延迟20 ms

```text
A5 5A 01 07 00 00 E8 03 14 00 99 9A
```

含义：

- sequence=`1`
- flags=`0x07`
- position=`0`
- confidence=`1000`
- delay=`20 ms`
- CRC=`0x9A99`

### 7.2 +50.0 mm、置信度850、延迟18 ms

```text
A5 5A 2A 07 F4 01 52 03 12 00 D4 3D
```

### 7.3 -50.0 mm、置信度900、延迟22 ms

```text
A5 5A 2B 07 0C FE 84 03 16 00 2E D5
```

### 7.4 通信正常但没有识别到球

```text
A5 5A 2C 06 00 00 00 00 14 00 8F 7B
```

`0x06`表示标定有效、摄像头正常，但 `BALL_FOUND=0`。

双方实现必须对上述测试向量得到完全一致的结果。

## 8. gugaPI接收状态

gugaPI解析器维护：

- 接收字节数；
- CRC正确帧数；
- CRC错误数；
- 帧头重同步次数；
- 序号跳变和重复次数；
- 最新正确帧接收时间；
- 最新有效球位置时间；
- 当前通信状态和球识别状态。

默认判定：

| 条件 | 处理 |
| --- | --- |
| 正确帧年龄不超过100 ms | 通信在线 |
| 超过100 ms无正确帧 | 通信超时 |
| 有效球位置年龄不超过60 ms | 正常控制 |
| 60～120 ms | 短时预测、冻结积分、限制梁角 |
| 超过120 ms无有效球位置 | 当前滚球任务失败 |
| `abs(position)>1150` | 接近端部，立即停止车辆运动 |

通信超时或球丢失只在H3/H4/H5或其他滚球动作运行时升级为任务失败。H2不依赖MaixCAM。

## 9. 解析与重同步

gugaPI接收流程：

1. 搜索连续字节 `A5 5A`；
2. 收满剩余10字节；
3. 计算字节0～9的CRC；
4. CRC正确后检查状态、置信度和范围；
5. 发布样本并更新时间；
6. CRC错误时从当前缓存的下一个字节重新搜索帧头。

解析器不得忙等剩余字节，不得在UART ISR内计算CRC、格式化日志或执行控制。

## 10. 双方交付与联调

MaixCAM侧交付：

- 固定12字节打包函数；
- 50 Hz自动发送任务；
- 物理坐标标定说明；
- 上述四组测试向量的单元测试；
- 有球、无球、遮挡和摄像头异常的串口日志。

gugaPI侧交付：

- UART非阻塞接收；
- 帧解析和CRC主机测试；
- `vision status/stats/clear`；
- `vision inject`调试入口；
- PC串口模拟发送脚本；
- 通信超时和球丢失安全测试。

联调顺序：

1. 双方离线验证固定测试向量；
2. PC模拟MaixCAM向gugaPI发送；
3. MaixCAM固定发送O点；
4. 手动移动钢球验证正负方向和比例；
5. 遮挡钢球验证 `BALL_FOUND=0`；
6. 拔掉串口验证100 ms通信超时；
7. 最后连接BallBalance和DM-G6220闭环。
